# BUILD SIGNAL

전국 건설현장 영업정보 플랫폼 MVP. Node.js + Express + Neon PostgreSQL 기반이며 PC/모바일 반응형 웹을 제공합니다.

## 회원 시스템 (v1.1)
- 이메일 회원가입 및 비밀번호 해시 저장(bcrypt)
- 로그인/로그아웃 및 PostgreSQL 기반 서버 세션
- 신규 가입은 관리자 승인 후 이용 가능
- 관리자 회원 목록, 승인 및 삭제
- 관심 현장과 영업 메모는 회원별 분리 저장
- 관리자 계정은 Render의 `ADMIN_EMAIL`, `ADMIN_PASSWORD` 환경변수로 최초 생성/갱신

## 현재 포함된 기능
- 대시보드 통계 및 신규 리드 요약
- 전국 현장 검색(지역, 공사단계, 건물용도, 키워드)
- 현장 상세 및 발주처/건축주/설계사/감리사/시공사 표시
- 관심현장 및 영업 파이프라인 관리
- 업종별 AI 영업 적합도 규칙 기반 점수(초기 MVP)
- CSV/엑셀 호환 다운로드
- 관리자용 데모 데이터 생성 및 API 데이터 적재 엔드포인트
- Neon PostgreSQL 자동 테이블 생성
- Render 배포 설정

## 중요: 데이터에 관한 안내
초기 배포는 `DATA_SOURCE_MODE=demo`로 동작하며 화면 검증용 샘플 데이터가 표시됩니다. 샘플은 실제 현장이나 실제 기업정보가 아닙니다.
실제 전국 현장 데이터는 건축HUB/세움터 등 제공기관의 이용 승인·API 명세·상업적 이용 및 재배포 조건을 확인한 후 연결해야 합니다. 본 프로젝트에는 출처를 위장하거나 존재하지 않는 공공 API를 호출하는 코드를 넣지 않았습니다.
실제 API 키만 넣으면 전국 현장정보가 자동으로 확보되는 상태는 아닙니다. 기관별 API 응답 스키마에 맞춘 어댑터 구현 및 데이터 품질 검증이 후속 작업입니다.

## 로컬 실행
1. Node.js 20 이상 설치
2. `npm install`
3. `.env.example`을 `.env`로 복사하고 DATABASE_URL, ADMIN_EMAIL, ADMIN_PASSWORD, SESSION_SECRET 입력
4. `npm start`
5. 브라우저에서 `http://localhost:10000`

## 회원가입 및 관리자 승인
1. 배포 후 `/login.html`에서 관리자 이메일/비밀번호로 로그인합니다.
2. 일반 사용자는 회원가입 탭에서 회사명, 담당자, 이메일, 비밀번호를 등록합니다.
3. 신규 가입자는 `pending` 상태로 저장되며 승인 전에는 로그인할 수 없습니다.
4. 관리자는 상단의 `회원관리`에서 가입자를 승인하거나 삭제할 수 있습니다.
5. 관리자 이메일/비밀번호는 Render 환경변수 `ADMIN_EMAIL`, `ADMIN_PASSWORD`와 일치해야 합니다. 서버 시작 시 해당 계정은 관리자 권한으로 보장됩니다.

## Render + Neon 배포
1. ZIP 압축을 풀고 GitHub 저장소에 전체 파일 업로드
2. Neon에서 PostgreSQL 프로젝트 생성 후 connection string 복사
3. Render에서 New > Web Service > GitHub 저장소 선택
4. Build Command: `npm install`
5. Start Command: `npm start`
6. 환경변수 설정:
   - `DATABASE_URL`: Neon connection string (`?sslmode=require` 포함 권장)
   - `ADMIN_EMAIL`: 관리자 이메일
   - `ADMIN_PASSWORD`: 강력한 관리자 비밀번호
   - `SESSION_SECRET`: 길고 임의적인 비밀 문자열
   - `DATA_SOURCE_MODE`: 처음에는 `demo`
7. 배포 후 `/api/health` 확인

## 관리자 및 보안
- MVP 관리자 로그인: `/login`
- 관리자 계정은 Render 환경변수로 설정합니다.
- 로그인은 단일 관리자 계정 기반의 초기 MVP입니다. 공개 서비스 전에는 사용자별 계정, 비밀번호 해시, 세션 저장소, CSRF 보호, 역할별 권한, 감사로그를 추가해야 합니다.
- 현재 API 적재 엔드포인트는 `ADMIN_INGEST_TOKEN` 환경변수 설정 시 `x-ingest-token` 헤더 검증을 수행합니다. 해당 값을 반드시 강력한 값으로 설정하세요.

## 데이터 적재 API
`POST /api/ingest/projects`
Headers:
`Content-Type: application/json`
`x-ingest-token: <ADMIN_INGEST_TOKEN>`

Body:
```json
{
  "source": "기관명/데이터셋명",
  "projects": [
    {
      "externalId": "source-row-id",
      "name": "프로젝트명",
      "address": "도로명 또는 지번 주소",
      "region": "서울특별시",
      "district": "강남구",
      "buildingType": "업무시설",
      "stage": "PERMIT",
      "permitDate": "2026-01-15",
      "startDate": null,
      "completionDate": null,
      "floorsAbove": 15,
      "floorsBelow": 3,
      "areaSqm": 12000,
      "estimatedCost": null,
      "owner": "건축주/발주처",
      "designer": "설계사",
      "supervisor": "감리사",
      "contractor": "시공사",
      "sourceUrl": "https://...",
      "sourceUpdatedAt": "2026-01-15"
    }
  ]
}
```
`stage`: `PERMIT`, `STARTED`, `COMPLETED`, `BID`, `UNKNOWN`
중복 방지는 `source + externalId` 기준입니다. 같은 현장을 여러 출처에서 통합하는 고도화는 주소·허가번호 등 식별자 정규화 작업이 필요합니다.

## 보안 유의사항
- `SESSION_SECRET`은 충분히 길고 예측 불가능한 값으로 유지하고 외부에 공유하지 마세요.
- `ADMIN_PASSWORD`는 강력한 고유 비밀번호를 사용하세요.
- HTTPS(Render 기본 도메인) 환경에서 세션 쿠키는 Secure 옵션으로 전송됩니다.
- 상용 공개 전에는 CSRF 방어, 비밀번호 재설정/이메일 인증, 로그인 시도 제한, 개인정보 처리방침·이용약관을 추가하세요.
- 이 버전은 유료 결제/구독 기능은 포함하지 않습니다.


## 나라장터 입찰공고 API 연동 (v1.2)

Render 환경변수에 `G2B_SERVICE_KEY`를 등록합니다. 값은 공공데이터포털에서 발급한 일반 인증키(Decoding)를 사용합니다. 인증키를 소스코드나 GitHub에 저장하지 마세요.

관리자 계정으로 로그인한 뒤 회원관리(`/admin.html`) 화면의 **최근 7일 공고 수집** 버튼을 누르면 나라장터 공사 입찰공고를 조회하여 Neon DB에 저장합니다. 수집 결과 및 오류는 `ingest_logs`에 기록되고, 공고 고유번호와 차수로 중복을 갱신합니다.

현재 1회 최대 100건, 최근 최대 7일 조회로 제한했습니다. 나라장터 API의 상세 명세/요청 제한에 따라 실제 응답 확인 후 페이지네이션 및 자동 수집을 확장해야 합니다. 데이터가 수집되지 않으면 관리화면의 오류 메시지와 `ingest_logs`를 확인하세요.


### 국토교통부 건축HUB 수집

관리자 → 국토교통부 인허가·착공·준공 수집에서 인증키 설정 상태를 확인한 뒤 지역코드로 실행합니다. `ARCH_HUB_SERVICE_KEY`는 기존 건축HUB 키를 사용하며 추가 키는 필요하지 않습니다.

- 최초 적재: 한 법정동, 기간 조건 없이 최대 2,000건. 원천 응답이 제한을 넘으면 일부 저장 후 실패로 명시합니다. 이후 기간 지정/분할 수집이 필요합니다.
- 기간 지정: 한 법정동, 최대 30일. 기간 조건은 원천 API 검색 기준으로 실제 사건 날짜와 동일하다고 가정하지 않습니다.
- 공식 `getApBasisOulnInfo` 응답의 `archPmsDay`(건축허가일), `realStcnsDay`(실제착공일), `useAprDay`(사용승인일)를 각각 저장합니다. 최신 단계는 사용승인 → 착공 → 인허가 순으로 판단합니다. 준공 표시는 사용승인 기준이며 별도의 공사 완료 예정일로 추정하지 않습니다.
- 동일 관리허가대장 PK 재수집은 갱신하며, 빈 날짜가 기존에 확인된 날짜와 단계를 지우지 않습니다.
- 저장 현황은 DB 전체 건수, 실행 결과의 단계별 수는 해당 실행에서 처리한 행 수입니다. 전국 자동 적재가 아닙니다.
- 운영 API/DB 저장 검증은 실제 관리자 수집 실행이 필요합니다. 로컬 검증: `node --test test/archhub.test.js`.

출처: 국토교통부 건축HUB 건축인허가정보 공식 OpenAPI 활용가이드 1.0, 기본개요 응답 명세(사용승인일 포함).


### 서버 자동 수집 (상시 실행)

서버 시작 후 자동으로 시작하며, 브라우저 방문·관리자 로그인·매일 버튼 조작에 의존하지 않습니다. 별도 ChatGPT 예약 작업은 사용하지 않습니다. DB 스키마는 기존 `initDb()`가 생성합니다.

- 나라장터: 최초 최근 7일을 적재하고 성공한 시간 구간을 DB에 저장합니다. 이후 하루마다 마지막 성공 지점부터 2시간을 겹쳐 갱신합니다. 실패 구간 이후로 진행하지 않고 30분 후 재시도합니다. 오랜 중단은 실행당 최대 7일씩 따라잡습니다.
- 국토부: 등록 지역을 전체 기간으로 페이지당 100건씩 순회합니다. 페이지 위치를 DB에 저장하므로 2,000건 이후도 다음 실행에서 이어 갑니다. 지역 한 바퀴 완료 후 24시간이 지나면 다시 조회해 기존 현장의 착공·사용승인 변화도 반영합니다. 신규 지역 수집과 기존 자료 갱신을 동일하게 수행합니다.
- 지역 범위: 서비스에 내장한 공식 전국 법정동코드를 서버 시작 시 자동 등록하며, 활성 코드를 매시간 자동 수집 대상에 반영합니다. 사용자·관리자의 코드 입력이나 파일 등록은 필요하지 않습니다. 전국 자료는 호출 한도 내에서 순차 적재되므로 모든 지역이 즉시 검색되는 것은 아닙니다.
- 호출량: 기본 자동 국토부 500회/일, 나라장터 1,000회/일(KST). 재시도도 포함합니다. 실제 발급키 한도가 더 작으면 아래 값을 낮춰야 합니다. 수동 수집 호출은 별도입니다. 국토부는 기본 1분마다 최대 5페이지를 처리하며 호출량에 따라 모든 지역의 순회에는 하루 이상 걸릴 수 있습니다. 최근 처리 성공 시각은 전체 지역의 최신성을 의미하지 않습니다.
- 재시작/중복 실행: DB 실행권, 유효기간, 하트비트로 자동 작업의 중복 실행을 제한합니다. 성공한 페이지/시간 구간만 진행을 저장하며 재시작 후 미완료 지점부터 재개합니다. 중간에 저장된 행이 재처리되어도 출처/PK로 갱신합니다.
- 서버가 항상 실행되어 있어야 합니다. 서버 정지·절전 중에는 수집되지 않으며 재가동 시 재개합니다. 사용자 화면의 자동 갱신 상태에서 마지막 처리 성공과 국토부 순회 범위를 확인할 수 있습니다.

선택 환경변수: `AUTO_INGEST_ENABLED=false`로 중지, `AUTO_PERMIT_DAILY_REQUESTS=500`, `AUTO_G2B_DAILY_REQUESTS=1000`, `AUTO_PERMIT_PAGES_PER_TICK=5`. 기존 두 서비스 인증키와 DATABASE_URL을 그대로 사용합니다. 별도 유료 서비스나 추가 계정은 필요하지 않습니다.


### 지역 선택과 내장 전국 코드

회원 화면의 두 검색 탭에서 전체·서울·경기 등 지역을 선택합니다. 선택값은 검색 조건이며 즉시 원천 API를 호출하거나 수집 범위를 바꾸지 않습니다. 이전 지역명도 검색할 수 있도록 별칭을 지원합니다.

`data/legal-dong.json.gz`에는 행정표준코드관리시스템의 공식 전체 자료 중 현존 코드만 포함합니다. `legal-dong-meta.json`에 확보일·출처·해시를 기록하고, 시작 시 무결성을 검사합니다. 버전이 바뀔 때 DB에 반영하고 동일 버전은 재적재하지 않습니다. 사용자의 수동 등록 자료를 지우지 않습니다.

최신 코드 스냅샷 갱신은 개발 유지보수에서 `python3 scripts/update-region-catalog.py` 후 데이터 파일을 배포하면 됩니다. 운영 관리자에게 매일 수행하도록 요구하는 절차가 아닙니다. 원천 변경을 실시간 자동 반영하는 기능은 포함하지 않습니다.


### 초기 사업과 단계별 참여업체 (1차 연결)

일반 현장 검색에서 `심의` 단계를 선택하거나 키워드에 `심의`를 입력합니다. 서버는 하루 한 번 울산 남구 건축위원회 게시판 첫 페이지에서 최근 지원 형식의 게시물 최대 4건을 읽고, 검증한 군산시 PDF 1건을 함께 처리합니다. 추가 API 키 없이 기존 자동 수집 설정을 따릅니다. 전국 지자체 심의자료 전체 수집이나 HWP/HWPX 파싱은 아직 포함하지 않습니다.

- 울산 남구: 원문 본문의 안건별 신청인·위치·용도와 명시된 역할만 추출합니다. 게시판의 담당 공무원 번호를 현장 연락처로 복사하지 않습니다.
- 군산: 확인한 단일 사업 PDF 서식의 건축주·주소·심의일을 추출합니다. 임의의 PDF를 같은 서식으로 간주하지 않습니다.
- 역할은 건축주, 사업시행자, 신청인, 설계사, 시공사, 감리사, 운영·관리사로 분리합니다. 자동 추출은 미확인 상태로 원문과 함께 표시하며, 회사 연락처와 프로젝트 담당 연락처를 구분합니다. 공개된 연락처가 없는 경우 생성하지 않습니다.
- 출처 URL·역할·확인 단계·수집 시각·근거 문장을 누적 저장합니다. 같은 근거는 중복 등록하지 않으며 내용 변경은 과거 기록을 덮어쓰지 않고 새 근거로 남깁니다.
- 원문 위치가 같아도 여러 사업일 수 있으므로 심의와 인허가를 자동 병합하지 않습니다. 관리자 '심의 단계 사업·참여업체'에서 두 현장 ID와 판단 근거를 확인해 연결하면 인허가 상세 화면에 심의 근거와 진행 이력을 함께 표시합니다. 직접 연결은 심의 출처→국토부 인허가 출처만 허용하고 기존 연결을 자동 변경하지 않습니다.
- 관리자 공식 근거 등록은 `.go.kr` HTTPS URL만 허용합니다. 회사 명부·외부 홈페이지 자동 연락처 보완은 아직 연결하지 않았습니다.
- HTML 구조·PDF 서식이 다르면 처리 실패로 기록하고 재확인이 필요함을 표시합니다. 문서별 최대 8MB, 동시 실행 방지 DB 실행권, 하루 최대 50회 자동 자료 요청을 적용합니다. 실패 시 일부 자료는 등록되지 않을 수 있습니다.
