# BUILD SIGNAL

전국 건설현장 영업정보 플랫폼 MVP. Node.js + Express + Neon PostgreSQL 기반이며 PC/모바일 반응형 웹을 제공합니다.

## 회원 시스템 (v1.1)
- 이메일 회원가입 및 비밀번호 해시 저장(bcrypt)
- 로그인/로그아웃 및 PostgreSQL 기반 서버 세션
- 신규 가입은 관리자 승인 후 이용 가능
- 관리자 회원 목록, 승인 및 삭제
- 관심 현장과 영업 메모는 회원별 분리 저장
- 관리자 계정은 Render의 `ADMIN_EMAIL`, `ADMIN_PASSWORD` 환경변수로 최초 생성/갱신

## 현재 포함된 기능
- 대시보드 통계 및 신규 리드 요약
- 전국 현장 검색(지역, 공사단계, 건물용도, 키워드)
- 현장 상세 및 발주처/건축주/설계사/감리사/시공사 표시
- 관심현장 및 영업 파이프라인 관리
- 업종별 AI 영업 적합도 규칙 기반 점수(초기 MVP)
- CSV/엑셀 호환 다운로드
- 관리자용 데모 데이터 생성 및 API 데이터 적재 엔드포인트
- Neon PostgreSQL 자동 테이블 생성
- Render 배포 설정

## 중요: 데이터에 관한 안내
초기 배포는 `DATA_SOURCE_MODE=demo`로 동작하며 화면 검증용 샘플 데이터가 표시됩니다. 샘플은 실제 현장이나 실제 기업정보가 아닙니다.
실제 전국 현장 데이터는 건축HUB/세움터 등 제공기관의 이용 승인·API 명세·상업적 이용 및 재배포 조건을 확인한 후 연결해야 합니다. 본 프로젝트에는 출처를 위장하거나 존재하지 않는 공공 API를 호출하는 코드를 넣지 않았습니다.
실제 API 키만 넣으면 전국 현장정보가 자동으로 확보되는 상태는 아닙니다. 기관별 API 응답 스키마에 맞춘 어댑터 구현 및 데이터 품질 검증이 후속 작업입니다.

## 로컬 실행
1. Node.js 20 이상 설치
2. `npm install`
3. `.env.example`을 `.env`로 복사하고 DATABASE_URL, ADMIN_EMAIL, ADMIN_PASSWORD, SESSION_SECRET 입력
4. `npm start`
5. 브라우저에서 `http://localhost:10000`

## 회원가입 및 관리자 승인
1. 배포 후 `/login.html`에서 관리자 이메일/비밀번호로 로그인합니다.
2. 일반 사용자는 회원가입 탭에서 회사명, 담당자, 이메일, 비밀번호를 등록합니다.
3. 신규 가입자는 `pending` 상태로 저장되며 승인 전에는 로그인할 수 없습니다.
4. 관리자는 상단의 `회원관리`에서 가입자를 승인하거나 삭제할 수 있습니다.
5. 관리자 이메일/비밀번호는 Render 환경변수 `ADMIN_EMAIL`, `ADMIN_PASSWORD`와 일치해야 합니다. 서버 시작 시 해당 계정은 관리자 권한으로 보장됩니다.

## Render + Neon 배포
1. ZIP 압축을 풀고 GitHub 저장소에 전체 파일 업로드
2. Neon에서 PostgreSQL 프로젝트 생성 후 connection string 복사
3. Render에서 New > Web Service > GitHub 저장소 선택
4. Build Command: `npm install`
5. Start Command: `npm start`
6. 환경변수 설정:
   - `DATABASE_URL`: Neon connection string (`?sslmode=require` 포함 권장)
   - `ADMIN_EMAIL`: 관리자 이메일
   - `ADMIN_PASSWORD`: 강력한 관리자 비밀번호
   - `SESSION_SECRET`: 길고 임의적인 비밀 문자열
   - `DATA_SOURCE_MODE`: 처음에는 `demo`
7. 배포 후 `/api/health` 확인

## 관리자 및 보안
- MVP 관리자 로그인: `/login`
- 관리자 계정은 Render 환경변수로 설정합니다.
- 로그인은 단일 관리자 계정 기반의 초기 MVP입니다. 공개 서비스 전에는 사용자별 계정, 비밀번호 해시, 세션 저장소, CSRF 보호, 역할별 권한, 감사로그를 추가해야 합니다.
- 현재 API 적재 엔드포인트는 `ADMIN_INGEST_TOKEN` 환경변수 설정 시 `x-ingest-token` 헤더 검증을 수행합니다. 해당 값을 반드시 강력한 값으로 설정하세요.

## 데이터 적재 API
`POST /api/ingest/projects`
Headers:
`Content-Type: application/json`
`x-ingest-token: <ADMIN_INGEST_TOKEN>`

Body:
```json
{
  "source": "기관명/데이터셋명",
  "projects": [
    {
      "externalId": "source-row-id",
      "name": "프로젝트명",
      "address": "도로명 또는 지번 주소",
      "region": "서울특별시",
      "district": "강남구",
      "buildingType": "업무시설",
      "stage": "PERMIT",
      "permitDate": "2026-01-15",
      "startDate": null,
      "completionDate": null,
      "floorsAbove": 15,
      "floorsBelow": 3,
      "areaSqm": 12000,
      "estimatedCost": null,
      "owner": "건축주/발주처",
      "designer": "설계사",
      "supervisor": "감리사",
      "contractor": "시공사",
      "sourceUrl": "https://...",
      "sourceUpdatedAt": "2026-01-15"
    }
  ]
}
```
`stage`: `PERMIT`, `STARTED`, `COMPLETED`, `BID`, `UNKNOWN`
중복 방지는 `source + externalId` 기준입니다. 같은 현장을 여러 출처에서 통합하는 고도화는 주소·허가번호 등 식별자 정규화 작업이 필요합니다.

## 보안 유의사항
- `SESSION_SECRET`은 충분히 길고 예측 불가능한 값으로 유지하고 외부에 공유하지 마세요.
- `ADMIN_PASSWORD`는 강력한 고유 비밀번호를 사용하세요.
- HTTPS(Render 기본 도메인) 환경에서 세션 쿠키는 Secure 옵션으로 전송됩니다.
- 상용 공개 전에는 CSRF 방어, 비밀번호 재설정/이메일 인증, 로그인 시도 제한, 개인정보 처리방침·이용약관을 추가하세요.
- 이 버전은 유료 결제/구독 기능은 포함하지 않습니다.


## 나라장터 입찰공고 API 연동 (v1.2)

Render 환경변수에 `G2B_SERVICE_KEY`를 등록합니다. 값은 공공데이터포털에서 발급한 일반 인증키(Decoding)를 사용합니다. 인증키를 소스코드나 GitHub에 저장하지 마세요.

관리자 계정으로 로그인한 뒤 회원관리(`/admin.html`) 화면의 **최근 7일 공고 수집** 버튼을 누르면 나라장터 공사 입찰공고를 조회하여 Neon DB에 저장합니다. 수집 결과 및 오류는 `ingest_logs`에 기록되고, 공고 고유번호와 차수로 중복을 갱신합니다.

현재 1회 최대 100건, 최근 최대 7일 조회로 제한했습니다. 나라장터 API의 상세 명세/요청 제한에 따라 실제 응답 확인 후 페이지네이션 및 자동 수집을 확장해야 합니다. 데이터가 수집되지 않으면 관리화면의 오류 메시지와 `ingest_logs`를 확인하세요.


### 국토교통부 건축HUB 수집

관리자 → 국토교통부 인허가·착공·준공 수집에서 인증키 설정 상태를 확인한 뒤 지역코드로 실행합니다. `ARCH_HUB_SERVICE_KEY`는 기존 건축HUB 키를 사용하며 추가 키는 필요하지 않습니다.

- 최초 적재: 한 법정동, 기간 조건 없이 최대 2,000건. 원천 응답이 제한을 넘으면 일부 저장 후 실패로 명시합니다. 이후 기간 지정/분할 수집이 필요합니다.
- 기간 지정: 한 법정동, 최대 30일. 기간 조건은 원천 API 검색 기준으로 실제 사건 날짜와 동일하다고 가정하지 않습니다.
- 공식 `getApBasisOulnInfo` 응답의 `archPmsDay`(건축허가일), `realStcnsDay`(실제착공일), `useAprDay`(사용승인일)를 각각 저장합니다. 최신 단계는 사용승인 → 착공 → 인허가 순으로 판단합니다. 준공 표시는 사용승인 기준이며 별도의 공사 완료 예정일로 추정하지 않습니다.
- 동일 관리허가대장 PK 재수집은 갱신하며, 빈 날짜가 기존에 확인된 날짜와 단계를 지우지 않습니다.
- 저장 현황은 DB 전체 건수, 실행 결과의 단계별 수는 해당 실행에서 처리한 행 수입니다. 전국 자동 적재가 아닙니다.
- 운영 API/DB 저장 검증은 실제 관리자 수집 실행이 필요합니다. 로컬 검증: `node --test test/archhub.test.js`.

출처: 국토교통부 건축HUB 건축인허가정보 공식 OpenAPI 활용가이드 1.0, 기본개요 응답 명세(사용승인일 포함).


### 서버 자동 수집 (상시 실행)

서버 시작 후 자동으로 시작하며, 브라우저 방문·관리자 로그인·매일 버튼 조작에 의존하지 않습니다. 별도 ChatGPT 예약 작업은 사용하지 않습니다. DB 스키마는 기존 `initDb()`가 생성합니다.

- 나라장터: 최초 최근 7일을 적재하고 성공한 시간 구간을 DB에 저장합니다. 이후 하루마다 마지막 성공 지점부터 2시간을 겹쳐 갱신합니다. 실패 구간 이후로 진행하지 않고 30분 후 재시도합니다. 오랜 중단은 실행당 최대 7일씩 따라잡습니다.
- 국토부: 등록 지역을 전체 기간으로 페이지당 100건씩 순회합니다. 페이지 위치를 DB에 저장하므로 2,000건 이후도 다음 실행에서 이어 갑니다. 지역 한 바퀴 완료 후 24시간이 지나면 다시 조회해 기존 현장의 착공·사용승인 변화도 반영합니다. 신규 지역 수집과 기존 자료 갱신을 동일하게 수행합니다.
- 지역 범위: 서비스에 내장한 공식 전국 법정동코드를 서버 시작 시 자동 등록하며, 활성 코드를 매시간 자동 수집 대상에 반영합니다. 사용자·관리자의 코드 입력이나 파일 등록은 필요하지 않습니다. 전국 자료는 호출 한도 내에서 순차 적재되므로 모든 지역이 즉시 검색되는 것은 아닙니다.
- 호출량: 기본 자동 국토부 500회/일, 나라장터 1,000회/일(KST). 재시도도 포함합니다. 실제 발급키 한도가 더 작으면 아래 값을 낮춰야 합니다. 수동 수집 호출은 별도입니다. 국토부는 기본 1분마다 최대 5페이지를 처리하며 호출량에 따라 모든 지역의 순회에는 하루 이상 걸릴 수 있습니다. 최근 처리 성공 시각은 전체 지역의 최신성을 의미하지 않습니다.
- 재시작/중복 실행: DB 실행권, 유효기간, 하트비트로 자동 작업의 중복 실행을 제한합니다. 성공한 페이지/시간 구간만 진행을 저장하며 재시작 후 미완료 지점부터 재개합니다. 중간에 저장된 행이 재처리되어도 출처/PK로 갱신합니다.
- 서버가 항상 실행되어 있어야 합니다. 서버 정지·절전 중에는 수집되지 않으며 재가동 시 재개합니다. 사용자 화면의 자동 갱신 상태에서 마지막 처리 성공과 국토부 순회 범위를 확인할 수 있습니다.

선택 환경변수: `AUTO_INGEST_ENABLED=false`로 중지, `AUTO_PERMIT_DAILY_REQUESTS=500`, `AUTO_G2B_DAILY_REQUESTS=1000`, `AUTO_PERMIT_PAGES_PER_TICK=5`. 기존 두 서비스 인증키와 DATABASE_URL을 그대로 사용합니다. 별도 유료 서비스나 추가 계정은 필요하지 않습니다.


### 지역 선택과 내장 전국 코드

회원 화면의 두 검색 탭에서 전체·서울·경기 등 지역을 선택합니다. 선택값은 검색 조건이며 즉시 원천 API를 호출하거나 수집 범위를 바꾸지 않습니다. 이전 지역명도 검색할 수 있도록 별칭을 지원합니다.

`data/legal-dong.json.gz`에는 행정표준코드관리시스템의 공식 전체 자료 중 현존 코드만 포함합니다. `legal-dong-meta.json`에 확보일·출처·해시를 기록하고, 시작 시 무결성을 검사합니다. 버전이 바뀔 때 DB에 반영하고 동일 버전은 재적재하지 않습니다. 사용자의 수동 등록 자료를 지우지 않습니다.

최신 코드 스냅샷 갱신은 개발 유지보수에서 `python3 scripts/update-region-catalog.py` 후 데이터 파일을 배포하면 됩니다. 운영 관리자에게 매일 수행하도록 요구하는 절차가 아닙니다. 원천 변경을 실시간 자동 반영하는 기능은 포함하지 않습니다.


### 초기 사업과 단계별 참여업체 (1차 연결)

일반 현장 검색에서 `심의` 단계를 선택하거나 키워드에 `심의`를 입력합니다. 서버는 하루 한 번 울산 남구 건축위원회 게시판 첫 페이지에서 최근 지원 형식의 게시물 최대 4건을 읽고, 검증한 군산시 PDF 1건을 함께 처리합니다. 추가 API 키 없이 기존 자동 수집 설정을 따릅니다. 전국 지자체 심의자료 전체 수집이나 HWP/HWPX 파싱은 아직 포함하지 않습니다.

- 울산 남구: 원문 본문의 안건별 신청인·위치·용도와 명시된 역할만 추출합니다. 게시판의 담당 공무원 번호를 현장 연락처로 복사하지 않습니다.
- 군산: 확인한 단일 사업 PDF 서식의 건축주·주소·심의일을 추출합니다. 임의의 PDF를 같은 서식으로 간주하지 않습니다.

- **업체명만 일치하면 미확인 후보입니다.** 참여업체 근거에 기록된 회사 사업장 주소 또는 등록번호까지 일치할 때 식별정보 일치로 표시합니다. 공사현장 주소를 회사 사업장 주소로 대체하지 않습니다. 업체명 정규화는 법인 표기·공백 정도만 처리하고 유사 이름으로 자동 확정하지 않습니다.
- 관리자는 명부 ID와 참여업체 근거 ID, 확인 이유를 기록해 동일 업체 확인 또는 후보 제외를 할 수 있습니다. 판단은 이력으로 보존합니다. 이후 같은 출처·업체명·사업장 주소·등록번호의 업체는 확인 판단을 재사용합니다. 명부가 바뀌어도 이전 확인 기록은 남으며, 이전 명부 전화는 갱신 확인이 필요하다고 표시합니다.

- API는 코드와 문서 명세를 확인한 연결이며 실제 인증된 호출과 운영 DB 반영은 별도 검증이 필요합니다. 공개 다운로드 자료는 로컬에서 실제 수신·정규화를 검증했습니다.

### 경기부동산포털 공개 명부

경기도청 사전정보공표의 '부동산개발업 현황'이 연결하는 `https://gris.gg.go.kr/reb/selectRealestateDevList.do` 공개 목록을 사용합니다. 추가 키 없이 서버가 하루 한 번 전체 명부를 30건 단위로 읽습니다. 앞의 ODCloud 명부들은 기존 주 단위 갱신을 유지합니다. 명부의 원천 기준일이 목록에 없으므로 수집일을 기준일로 꾸며 표시하지 않습니다.

현장 참여 근거(`project_party_evidence`)에 있는 업체명과 같은 상호의 행에 대해서만 공개 전화 조회 버튼의 POST 양식으로 회사 전화번호를 확인합니다. 웹사이트가 발급한 익명 세션 쿠키와 CSRF 토큰을 정상 사용하며 로그인·캡차를 우회하지 않습니다. 확인한 번호도 동일 업체 확정 전에는 후보이며 현장 담당자의 직통번호로 표시하지 않습니다. 전화 조회가 없는 행은 미확인·미제공으로 남습니다.

등록번호가 있고 상호가 확인되지만 원문 사무소 주소가 비어 있는 행도 있습니다. 이 경우 사업장 주소를 빈 값으로 보존하고 현장 주소로 대체하지 않습니다. 주소가 없으면 주소를 근거로 동일 업체라고 판단하지 않습니다.

전체 건수·현재 페이지·표 머리글·행 구조·등록번호를 검증합니다. 페이지 중복, 누락, 조회 중 건수 변경, 전화 응답 형식 변경, 접속 실패가 있으면 기존 스냅샷을 유지하고 자동 재시도합니다. 1회 최대 10,000행·1,000요청·8분, 응답당 2MB 제한을 적용하며 기존 DB 실행권 안에서 처리합니다. 다수의 참여업체에 대한 전화 조회 등으로 실행 한도에 도달한 경우에도 부분 자료를 활성화하지 않습니다. 일일 수집은 서버의 `AUTO_INGEST_ENABLED` 설정을 따릅니다.

검증은 익명화한 공식 표 구조로 페이지 이어받기·오류 거부·세션 전달·참여업체 전화 조회·전체 스냅샷 활성화를 테스트합니다. 실제 원천 수신 검증 결과와 코드 검증 결과는 PR에 기록합니다. 운영 PostgreSQL·Render 반영 여부는 별도로 확인해야 합니다.


### 전국 순회 운영·지역별 연결 상태

국토부 자동 적재는 시·도별 최근 시도 시각이 오래된 순서로 번갈아 처리합니다. 해당 시·도 내에서는 예정 시각·마지막 시도·지역코드 순으로 법정동과 저장된 다음 페이지를 선택합니다. 따라서 한 시·도의 많은 초기 페이지가 다른 시·도의 첫 요청을 막지 않습니다. 지역별 일시 오류는 해당 법정동에 재시도 시각을 기록하고 다른 지역으로 진행합니다. 인증·접근 오류, 공통 일일 한도 소진과 실행권 상실은 전체 요청을 중지합니다. 성공한 페이지의 저장된 진행 위치는 유지합니다.

사용자 대시보드와 관리자 화면의 '전국 지역별 수집 범위 확인'에서 다음을 구분합니다. `/api/ingestion/coverage`는 내장 공식 현행 시·도 전체를 빠짐없이 반환하고 60초 동안 결과를 재사용합니다.

- 인허가·착공·준공: 법정동 대상 수, 시도 수, 전체 페이지 순회 완료 수, 최근 24시간 내 순회 수, 오류 지역 수. 최초 순회와 최신 갱신을 구분합니다. 순회가 완료되어도 해당 법정동의 실제 현장이 모두 공개되었다는 뜻은 아닙니다.
- 개발업체 회사 명부: 실제 연결한 지역 출처의 상태만 표시합니다. 건축사 전국 명부가 있다는 이유로 개발업체 명부도 전국이라고 표시하지 않습니다. 미연결 지역은 명확히 미연결로 남습니다.
- 심의자료: 서울시 공개목록에서 순차 탐색한 지원 형식 의결조서, 울산 남구 본문 일부와 군산 PDF 1건을 연결했으므로 해당 시·도도 '일부 출처'로 표시하고 그 외 지역은 미연결로 표시합니다.

최초 적재 최소 일수는 남은 법정동마다 최소 1회 요청하는 경우의 하한이며 실제 완료 예정일이 아닙니다. 기존 기본 한도 500회/일을 유지하므로 20,276개 대상은 최소 41일 이상이 걸릴 수 있습니다. 여러 페이지·실패·갱신 요청이 있으면 늘어납니다. 키의 승인 트래픽을 확인한 운영자는 `AUTO_PERMIT_DAILY_REQUESTS`를 승인 범위 안에서 변경할 수 있고 코드에서는 최대 10,000회/일까지 지원합니다. 자동화가 전국의 모든 자료를 하루 안에 확보하는 것으로 설명하면 안 됩니다.

전국 개발업체의 공식 단일 출처는 공공데이터포털 [국토교통부 부동산개발업정보(15123996)](https://www.data.go.kr/data/15123996/openapi.do)에서 확인했습니다. 제공처의 VWorld 상세 문서·서비스가 이번 확인에서 HTTP 503을 반환하여 실제 응답 필드 및 인증된 수집은 검증하지 못했습니다. 따라서 이 출처는 연결·필드 검증 대기로 표시하며 운영 수집기로 등록하지 않았습니다. 지자체 6개 지역 명부와 건축위원회 심의 3개 출처를 전국 구현 완료라고 보고하지 않습니다. 환경평가 공람의 전국 출처는 아래 별도 항목을 참조합니다.

### 서울시 건축위원회 의결조서 자동 수집

서울시 공식 [심의 결과 공개 게시판](https://news.seoul.go.kr/citybuild/architecture-committee-result)의 최신 게시글 10개를 매일 확인하면서 과거 목록을 페이지당 10개씩 순차 탐색합니다. 익명 열람·첨부 다운로드 권한이 공개된 게시물의 `심의의결조서(사업명).pdf`만 지원합니다. 과거 목록 탐색 기능이 있다고 모든 과거 PDF나 서울 자치구 전체 심의가 저장된 것은 아닙니다.

- 사업명·신청위치·심의일·의결번호·심의결과를 PDF의 명시된 표 머리글에서 추출하고, 파일명과 사업명·서울 자치구를 대조합니다. 여러 안건이 섞인 PDF나 변경된 서식은 오류로 남깁니다.
- `seoul_review` 출처와 `architectural_review_details`에 의결 내용을 저장합니다. 보류·조건부 수용을 허가·착공 완료로 바꾸지 않습니다. 이 서식에 없는 건축주·설계사·감리자·담당 연락처는 생성하지 않습니다. 상세 화면에 결과와 서울시 게시물 링크를 표시합니다.
- 발견한 첨부파일을 DB 큐에 보관하므로 서버 재시작 뒤에도 이어받습니다. 하루 100회 요청, 회당 PDF 10개·8분, 응답 2MB 제한입니다. 신규 첨부 우선, 정상 파일은 7일 뒤 재확인하고 파일 메타데이터가 바뀌면 다시 처리합니다. 파일 오류는 다른 안건의 저장을 막지 않고 2일 뒤 재시도합니다.
- 추가 인증키가 필요하지 않으며 `AUTO_INGEST_ENABLED=false`를 따릅니다. 동일 의결번호의 중복 게시는 한 기록으로 저장하지만 다른 회차 의결은 별도 기록입니다. 인허가 사업과의 연결은 관리자가 동일 사업 근거를 확인해야 합니다.
- PostgreSQL 실행 테스트로 큐 재개·중복 방지·오류 격리·트랜잭션 롤백·일일 요청 제한을 검증합니다. 운영 Render 배포와 Neon 적재 완료는 별도 확인 대상입니다.

2026-11-13에 확보한 서울시 공개 JSON·실제 PDF 2개를 수집기와 PostgreSQL 엔진에 재생하여 프로젝트 2건·의결기록 2건(보류 1건, 조건부 수용 1건)을 오류 없이 저장했습니다. 운영 DB에 저장한 결과가 아닙니다.


### 서울 과거 심의목록 순차 탐색과 진행 현황

`seoul_review_state.archive_page`에 과거 목록의 다음 페이지를, `seoul_review_posts`에 발견한 게시물과 재시도 일정을 저장합니다. 최신 목록은 매일 확인하며 과거 목록은 실행당 한 페이지를 추가합니다. 게시물 대기 20건 또는 PDF 대기 50건 이상이면 과거 탐색을 잠시 멈춰 처리 대기가 계속 늘어나지 않게 합니다. 목록의 실제 페이지·총건수·행 수·중복 ID를 검증하며 목록 오류나 호출 제한 시 그 페이지 위치를 유지합니다.

게시물 발견과 위치 갱신을 같은 트랜잭션으로 저장하고 첨부 확인은 별도 큐에서 회당 10건 처리합니다. 게시물 오류는 2일 뒤 재시도하며 다른 과거 페이지 진행을 막지 않습니다. 과거 목록 끝에 도달하면 7일 뒤 2페이지부터 다시 순회합니다. 게시물 삽입·삭제로 페이지 위치가 바뀔 수 있으므로 반복 순회하고 게시물 ID로 중복을 제거합니다. 한 번의 목록 순회가 과거 자료 전체 저장 완료를 보증하지 않습니다.

정상 확인한 과거 게시물의 첨부 목록은 30일 뒤 다시 확인합니다. 기존 PDF 재확인 주기는 7일, 하루 100회 요청 제한은 유지합니다. 신규·과거 자료 처리는 모두 같은 요청 예산을 사용하므로 완료 날짜를 고정해 약속하지 않습니다. 추가 설정이나 관리자 수동 버튼 없이 기존 자동 수집기에서 실행합니다.

`/api/ingestion/freshness`와 사용자·관리자 화면에서 발견 게시물, 첨부 확인 게시물, 지원 첨부가 없는 게시물, PDF 처리·오류 건수를 구분합니다. 관리자는 다음 과거 페이지와 최근 목록 순회 시점도 볼 수 있습니다. ‘미지원’은 지원 파일명·형식이 없는 게시물을 뜻하며 실제 심의나 참여업체 부재를 의미하지 않습니다. PostgreSQL 테스트에서 목록 장애 후 위치 유지, 서버 재시작 후 재개, 개별 게시물 재시도, 호출 제한에서 위치 보존, 중복 발견 제거를 검증합니다.


### 전국 심의 공개문서 발견 경로

국회도서관 [지방정책정보 공개검색](https://clik.nanet.go.kr/potal/search/searchList.do?collection=policyinfo&searchSelect=Y)의 공개 HTML을 지역 제한 없이 연결했습니다. 국회도서관 Open API는 별도 ID·인증키를 요구하므로 그 API를 호출하는 구현이 아닙니다. 익명 공개 목록과 상세 메타데이터만 읽고 DRM 첨부 다운로드·회원전용 자료를 처리하지 않습니다. 추가 인증키는 필요하지 않습니다.

- 원천 화면이 제공하는 전체·지역 미분류와 서울, 전남광주, 부산, 대구, 인천, 대전, 울산, 세종, 경기, 강원, 충북, 충남, 전북, 경북, 경남, 제주, 구 광주, 구 전남의 19개 검색 조건을 모두 등록합니다. 이 번호들은 법정동코드가 아니라 **원천 검색용 지역 필터**입니다. 공식 지역코드의 현행·기존 명칭과 연결하되 게시물 발행지역을 현장 위치로 간주하지 않습니다.
- 원천의 `searchGubun=pi`와 `piSearch=PQ@@REGION@@...`를 함께 사용하고 응답에 지역·검색어·컬렉션·페이지 조건이 실제 반영됐는지 검증합니다. 필터가 무시된 응답을 해당 지역 자료로 저장하지 않습니다. 결과 개수·행 번호·제어번호·중복을 검증하며 포함된 JSON을 JSON.parse로 읽습니다. 원천 JavaScript를 실행하지 않습니다.
- `national_review_streams`에 지역별 최신·과거 목록 순회 위치를 보존합니다. 최신 목록은 매일, 과거 목록은 회당 한 페이지씩 읽고 마지막 페이지 이후 7일 뒤 재순회합니다. 한 번에 4개 지역 조건을 번갈아 처리해 특정 지역 장애가 나머지를 막지 않도록 합니다. 문서 대기 100건 이상이면 과거 탐색을 잠시 멈춥니다.

### 심의 원문에서 현장·건축주 추출

전국 공개문서 발견 단계와 별도로 `review_extract` 자동 수집기를 실행합니다. 현재 검증된 서식은 **인천광역시 건축경관공동위원회의 PDF 결과표**입니다. [공식 게시판](https://www.incheon.go.kr/build/BU050101) 최신 심의결과 게시물 10개를 매일 확인하고, 전국 공개문서 색인에서 같은 게시판의 원문 링크를 발견한 경우에도 분석 목록에 추가합니다. 다른 지역·다른 서식 전체 또는 한글 파일 분석 완료가 아닙니다.

- 게시물 URL·첨부 upperNo·파일 번호를 대조하고 같은 게시물의 첨부만 처리합니다. 관련 글이나 미리보기 링크를 따라가지 않습니다. 허용한 인천 공식 경로만 읽고 리다이렉트를 허용하지 않습니다.
- 안건 경계, 표 머리글, 심의일자, 건축주 성명(법인명), 대지현황, 선택된 의결 체크박스를 검증합니다. 파일명에 연도·회차가 있으면 본문과 대조합니다. 여러 안건은 각각 분리하고 경계가 불분명한 PDF는 통째로 미지원 상태로 남깁니다. 공개문서 게시일을 심의일·허가일·착공일로 채우지 않습니다.
- 사업명·현장 주소·심의일·결과·공개된 건물 용도·연면적을 `document_review` 출처의 REVIEW 프로젝트로 저장합니다. 원문에서 명시한 건축주는 `project_party_evidence`의 owner 역할로 원문 URL·발췌 근거와 함께 저장합니다. 건축주를 시행사로 바꾸거나 행정기관·본문의 일반적인 설계자 지침을 참여업체로 채우지 않습니다. 가려진 건축주 이름도 복원하지 않습니다. 이번 서식에서 설계사·감리사·담당 연락처를 추출한다고 주장하지 않습니다.
- `review_extract_pages`·`review_extract_files`에 처리 위치·형식·오류·재시도를 보존합니다. 원문은 회당 게시물 5개·PDF 5개, 하루 100회 요청·8분 실행·응답 5MB·PDF 60페이지·텍스트 30만 자로 제한합니다. 지원하지 않는 한글·다른 PDF 서식은 미지원으로 표시합니다. 일반 오류는 2일, 서식 오류는 7일 뒤 재확인하며 같은 파일 실패가 나머지를 막지 않습니다. 정상 게시물·PDF도 7일 뒤 확인합니다.
